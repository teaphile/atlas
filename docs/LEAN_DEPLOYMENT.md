# Lean deployment and cleanup

Maintenance date: **18 October 2026**. This is an artifact cleanup, not an application-feature release.

## Kept

- Application backend and frontend source, all unit tests and reproducible browser test harnesses.
- Public map/style/font assets and all licence/attribution files.
- Locked Python/npm dependencies, Linux/Windows launchers, Docker/Compose/Caddy configuration and CI.
- Local configuration and the production SQLite cache; neither is included in the distributable.
- Architecture, scientific methods/model cards, API/account, security, local-run and deployment guides.
- Complete local Git history, including the original `v2.0.0` release tag.
- One `ATLAS-2.0-project.zip` plus its SHA-256 checksum, with the compiled frontend for runtime-only installation.

## Removed from the working tree

Historical screenshots, raw QA/audit logs, generated API sample dumps/schema copies, duplicate printable handovers, obsolete report-generation/review helpers and the redundant external Git bundle. The compact `docs/v2/release-verification.json` preserves the original validation summary.

Old tracked evidence is recoverable from the retained Git repository, for example:

```sh
git show v2.0.0:docs/v2/browser-verification-v2.json
git show v2.0.0:docs/audit-manifest.json
```

The release ZIP has no `.git` directory. Do not expect these historical Git commands to work in a standalone extracted ZIP.

## Deployment behavior

Production code, public assets, dependency locks and launch/deployment inputs were preserved. Docker's existing COPY steps use application source, dependency manifests and root licence notices; they do not read the removed reports. The live `/docs` and `/api/openapi.json` endpoints are generated by the backend, not by the deleted static schema dump.

Browser verification now writes to `.artifacts/browser/`; the optional read-only audit helper writes to `.artifacts/audit/`. These outputs are excluded from Git, Docker context and release ZIPs. Test harnesses create their output directories automatically.

Rebuild a distributable after changing application code:

```sh
cd frontend
npm ci --no-fund
npm run build
cd ..
python scripts/package_release.py
```

The packager verifies the new ZIP before replacing the previous release. The archive includes a per-file integrity manifest and has a separate SHA-256 checksum. A Git checkout needs the frontend build; the release ZIP already contains it. See `LOCAL_RUN.md` for runtime-only installation without Node.

## Cleanup verification

The existing cache was checkpointed through SQLite, **not** by deleting WAL/SHM files. Its 12 logical records were compared before/after, with identical contents and a successful integrity check. No cache records were removed.

The backend regression suite was repeated: **226 passed** (with zero warnings), plus **79 passed** frontend tests (**305 offline tests total**). Dependency consistency, full Ruff lint (`ruff check backend scripts`), Python syntax, strict TypeScript build and browser-script syntax checks passed.

The full historical frontend/browser matrix was not repeated for this artifact-only cleanup; its results remain dated in `VALIDATION.md`. No new Docker execution, public hosting, scientific calibration or production certification is claimed.

Additional checks: **88 protected source/test/configuration/asset/licence files** matched their pre-cleanup SHA-256 fingerprints. Local documentation links resolved. An isolated in-memory-cache application passed **37 API/documentation/static-file requests**, including all **30 compiled frontend files** with byte-for-byte HTTP responses. This did not start a public server or alter the real cache.
