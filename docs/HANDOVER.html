CHAPTER 02 / READ-ONLY UPSTREAM AUDIT

TerraWatch × OSIRIS — source-level review

Review date: 10 October 2026. Method: remote, read-only; no git clone; no execution of upstream applications.

Executive assessment

The complementary strengths are clear: TerraWatch is a Python-first environmental analysis service; OSIRIS is a multi-source geospatial operations interface. A literal merger would also combine incompatible data semantics, independent caches, different client/server assumptions and unvalidated numerical outputs. ATLAS therefore implements a new shared contract and a focused end-to-end product, rather than transplanting two application trees.

The most valuable improvement is not “more decimals” or an artificial intelligence label. It is preserving the distinction between observed events, model values, forecasts, bulletins, catalogs and publisher reports, with bounded resource use and traceable failure behavior.

TerraWatch: findings and implications

Source root: pinned TerraWatch tree.

TW-01 · Required-auth configuration can fail open

Evidence: backend/app/api/middleware/auth.py:41–48; backend/app/config.py:80–85.

The reviewed bypass condition accepts either authentication being disabled or the configured key being empty. The configuration path logs the invalid required-key state instead of rejecting startup. Thus a deployment that explicitly requests authentication but forgets its secret can remain accessible. This is a configuration-dependent finding, not evidence of an exploited deployment. Query-string key support also creates avoidable URL/history/log exposure.

ATLAS: startup rejects required authentication without a 32–256 character ASCII secret; header-only X-Atlas-Key; timing-safe comparison; input values hidden in settings validation errors. Tests cover absent/short/oversized/non-ASCII keys, query-key rejection and header acceptance. The frontend keeps its access key in page memory only.

TW-02 · Rainfall time scales and components need separation

Evidence: backend/app/services/disaster_service.py:185–193, 275.

The reviewed composition uses defaulted missing inputs and can add precipitation to rain, although the latter is a component of the former for the relevant weather API. Another path passes current-interval precipitation into a 24-hour quantity. These changes alter the meaning and magnitude of downstream inputs.

ATLAS: only the 24 completed hourly precipitation endpoints are summed; no rain double-counting; one missing hour makes the 24-hour total unknown. Tests cover missing, duplicate/future time handling and component separation. Values remain modeled rainfall, not rain-gauge measurements.

TW-03 · Heuristic scores are not calibrated probabilities

Evidence: backend/app/models/landslide_model.py:104–116; backend/app/models/flood_model.py:274–290; backend/app/services/disaster_service.py:314–317, 379+.

Weighted heuristic outputs, return-period labels and aggregation of unlike scores are not interchangeable with event probabilities or locally fitted frequency estimates. The disaster service itself contains an unvalidated-model disclosure; that qualification must survive into client presentation. Reviewed code paths do not establish site-specific calibration for transfer into a new product.

ATLAS: no flood/landslide/liquefaction probability, return period or universal disaster score is manufactured. The environmental attention index explicitly declares its designer-chosen weights, input coverage and missing-input sensitivity. River discharge is displayed as a model series, not inundation probability. RUSLE is a separate assumption-driven scenario.

TW-04 · Soil and crop confidence should not outgrow the data

Evidence: backend/app/models/soil_model.py:208–232, 267–270.

Heuristic/base-value and fixed-confidence paths do not demonstrate calibrated confidence in local crop performance. Soil model predictions are not lab samples, and total nitrogen is not automatically plant-available nitrogen.

ATLAS: ISRIC conversion factors, depth labels, null cells and surface Q05/Q95 predictions are retained. Carbon stock needs SOC, bulk density and coarse fragments at all three depths. Crop output is a deliberately limited pH-compatibility screen, not yield, fertilizer or suitability advice. No phosphorus/potassium values are invented from missing SoilGrids fields.

TW-05 · Short-window weather is not a climate normal

Evidence: backend/app/services/weather_service.py:431–466.

Annualizing a short rainfall window or substituting latitude-based climatology without a separate provenance label can make guessed climate inputs look observed.

ATLAS: no annualization of the recent forecast is used to create annual climate or erosion factors. NASA POWER is explicitly a delayed seven-day historical model context, not a 30-year climate normal. Annual RUSLE factors remain user-supplied assumptions.

TW-06 · Analytical vegetation fallback is not observed NDVI

Evidence: backend/app/services/satellite_service.py:42–54, 66–75.

An analytical NDVI-like fallback cannot establish satellite observation. The reviewed remote coverage/query assumptions also need live endpoint and measurement validation before being promoted as vegetation evidence.

ATLAS: genuine NASA GIBS imagery is offered with a date lag and cloud/gap warning. NDVI, crop stress, canopy health and biomass are not claimed or fabricated. A future Sentinel/Landsat workflow needs actual bands, QA masks, cloud screening and validated processing.

TW-07 · Useful existing engineering worth retaining conceptually

  • data/ingestion/soil_fetcher.py already uses repeated SoilGrids query keys and depth weighting; those are useful patterns. Two-decimal spatial cache keys and long retry paths still need attention for a field-scale interface.
  • The Hugging Face origin handling in backend/app/main.py:115–130 converts the wildcard into an anchored regular expression. It should not be reported as a broken literal wildcard CORS configuration.
  • The environmental service/model separation is a sound starting point. ATLAS preserves that separation instead of combining provider transport and scientific interpretation in one route.

OSIRIS: findings and implications

Source root: pinned OSIRIS tree.

OS-01 · Empty success versus last-good fallback

Evidence: src/lib/sourceCache.ts:58–79; associated source-cache tests were included in triage.

Keeping previous records after a valid empty result can resurrect events that have ended. Resetting cache time while retaining older content can also hide true age. Such retention can be a deliberate catalog-specific choice, but it is not a safe generic incident-feed rule.

ATLAS: validated empty payloads replace previous non-empty snapshots. Errors may retain last-good data only within the source's max-stale horizon, without resetting fetched_at. Cache miss, expiry, negative cache, storage errors, restart persistence and 100-caller single-flight behavior have offline tests.

OS-02 · SSRF defenses are substantial, not absent

Evidence: src/lib/ssrf-guard.ts:8–15, 118–163, 184–214.

The reviewed implementation rejects reserved IP ranges, resolves A/AAAA records and revalidates redirects. Its comments acknowledge the remaining socket-address-pinning/TOCTOU boundary. That is not, by itself, a demonstrated exploit.

ATLAS: deliberately narrower attack surface: no arbitrary-URL endpoint, exact HTTPS provider allowlist, no redirects and validated tile/camera identifiers. This does not constitute DNS/socket pinning; a production egress firewall and trusted DNS remain required defense in depth.

OS-03 · Provider diversity and asynchronous isolation are useful

Evidence: src/app/api/earthquakes/route.ts; fires/route.ts:18–19,44; weather/route.ts:175–189,312+.

USGS, FIRMS/EONET, NWS and GDACS integrations and all-settled-style aggregation are valuable. Geometry averaging, provider coverage differences and missing positions still require explicit semantics: an average point is not an impact footprint.

ATLAS: source failures are isolated. NWS null geometry remains unlocated; polygon summaries use a point inside the provider geometry where possible. Area reports test representative-point membership, not hazard footprint overlap or population exposure.

OS-04 · Mobility sources have credentials and temporal limits

Evidence: src/app/api/flights/route.ts; src/app/api/maritime/route.ts:98–140,214–215.

OpenSky OAuth/quota handling, an ADS-B fallback and AISstream's key/streaming-snapshot constraints are different operational products. The reviewed maritime path no longer relies on its earlier mock fallback; it should not be accused of doing so.

ATLAS: a reception-limited, opt-in ADSB.lol regional view and official TfL London cameras are implemented. AIS maritime, global camera aggregation and full orbital catalogs are explicitly deferred, not populated with dummy tracks. Position expiry, unknown capture time and regional coverage are visible.

OS-05 · Default analytics are a deployment choice

Evidence: src/middleware.ts:27–41.

The reviewed middleware sends internal Umami page/network telemetry that can include IP information. This is an operational/privacy choice, not proof of secret exfiltration.

ATLAS: no default visitor analytics, face recognition, owner enrichment or account profile. Selected coordinates/search terms still reach upstream providers, and cache keys retain query context; see the privacy section in SECURITY.md.

OS-06 · Simulation mechanics do not transfer calibration

Evidence: src/lib/oi/aggregate.ts:23–27,38–48,91–109 and neighboring OI code/tests inventoried in the manifest.

Weighted choices, simulated worlds and quantile aggregation can be valid computational tools. They do not establish a calibrated environmental forecast for the use case of this merger. The review does not claim to have disproved every forecast in OSIRIS.

ATLAS: bounded spatial-temporal proximity groups are an evidence-navigation tool, explicitly not corroboration, independent votes, probabilities or unique-incident resolution. No LLM-generated predictive oracle is presented as a scientific model.

4. Canonical records and clocks

An Event carries stable id, source_id, source_record_id, kind, nullable position, nullable issue/observation time, optional revision/expiry, display severity, nature, original URL and bounded attributes.

nature is one of observation, model, forecast, bulletin, catalog, or news. A source without a defensible position remains unlocated. No coordinates are invented from a publisher's headquarters or country label.

An Envelope adds status, fetched_at, checked_at, upstream_time, age, latency, error code, warnings and payload. These clocks have different meanings:

  • fetched_at: last successful retrieval/normalization, unchanged during fallback;
  • checked_at: last refresh attempt;
  • upstream_time: provider-supplied relevant timestamp when available;
  • occurred_at: individual record time, not silently replaced with the fetch time;
  • expires_at: record validity boundary, checked independently of source refresh.

Fresh transport does not imply a current observation. An annual population record can be freshly fetched without becoming live population. Source health describes the last served query for that adapter, not a globally measured provider uptime SLA.

5. Cache and recovery contract

  1. Normalize query context: coordinates to four decimal places; country and geocoding query have distinct keys. No two-decimal aliasing of soil cells.
  2. A fresh cache hit returns the original envelope with computed age.
  3. Concurrent misses share one task, including the disk lookup. Caller cancellation does not cancel shared ingestion.
  4. Validate upstream structure and normalization. A valid empty response replaces prior records.
  5. Save a successful last-good envelope; publish an invalidation. A write failure leaves the successful value usable in memory with a warning.
  6. On error, retain previous data only within the source's max-stale horizon. Do not re-date old data. Otherwise return unavailable with no old payload.
  7. A 60-second negative cache prevents failure storms. Admission caps bound total ingestion tasks.
  8. Restored fresh snapshots consume their remaining TTL; restart does not grant them a second full TTL. Failed collectors retry at a bounded cadence.

ISRIC gets a 22-second per-read allowance inside the existing bounded overall deadline; other sources use the configured HTTP timeout. The store is a last-good cache, not an archive. A browser timeline filters currently retained event times; it cannot reconstruct past aircraft tracks or historical provider states.

7. Spatial algorithms

AOI

Validate a Polygon, unwrap longitude around an anchor, reject self-intersections/oversize geometry, preserve holes and use boundary-inclusive membership. Date-line crossings are supported for regions under 180° wide. Area is a spherical approximation with holes subtracted, not an ellipsoidal cadastral survey.

Membership is against normalized observation points or provider representative points. It is not intersection with the full warning footprint, raster zonal statistics, population exposure or an impact perimeter.

Proximity groups

Convert eligible points to 3D Earth-centered coordinates. Hash into spatial cells and time buckets; inspect neighboring cells/buckets; apply a haversine distance and time-window check; join matches using union-find. This avoids naive all-pairs geographic joins and works around longitude wrap and near the poles. Candidate and comparison caps make dense scenes fail boundedly, with a truncation/budget flag.

Connected components are transitive: a chain can span more than the pairwise distance threshold. Default grouping is a proximity-navigation aid. Same location/time does not prove same event, independent corroboration or ground truth. Records from a downstream aggregator may share the same original instrument. The raw source records remain intact.

8. Frontend behavior and accessibility boundaries

  • Actual source data, not synthetic live fixtures. Network failures retain visible failure/stale state.
  • Global snapshots: SSE invalidations plus 30-second polling fallback. With a deployment key, polling is used because native EventSource cannot send that header.
  • Location models: concurrent current-condition requests; SoilGrids loads separately. Active-page environment refresh every 10 minutes; coordinate changes cancel obsolete client requests.
  • Aircraft: opt-in regional polling; browser position-age caps. Camera catalogs/images: opt-in official operator data, unknown capture time, not video.
  • Client filtering runs periodically (~10 seconds while active); background-tab browser throttling can delay visual expiry. Do not use it for navigation or emergency timing.
  • Saved views are local browser navigation state; restoring a view synchronizes the selected location/report. No account synchronization.
  • CSV neutralizes formula prefixes. JSON/GeoJSON preserve source/nature/time metadata and null positions.

9. Scaling boundary and next architecture

Run one application worker per deployment in this version. Multiple workers would duplicate polling, quotas, local caches and SSE state. SQLite is intentionally adequate for the demonstrated bounded single-process use case, not a distributed system hidden behind a demo.

For a multi-tenant/public service: separate collectors, shared rate/quota state in Redis, durable events and spatial indices in PostgreSQL/PostGIS, an object store for explicitly licensed history, a message broker for invalidation, tenant-scoped authorization and deployment-level egress controls. Add these after workload measurement, not as unused infrastructure labels.

Scientific expansion is separate: obtain defensible ground truth, hold out regions and time periods, validate/calibrate each hazard model, assess dependence and missingness, publish a model card and regional failure modes. Software tests alone cannot accomplish that.

ATLAS Signal Lab — method cards

Version: signal-lab-2.0.0. Research/exploration methods, not calibrated hazard models.

Data contract and time convention

  • Inputs: Open-Meteo numerical weather and CAMS air-quality model data. No sensor observations, training labels, downloaded model weights or LLM-generated values are added.
  • Existing weather/AQI requests ask for seven past days and five forecast calendar days. Five calendar days ensure the complete 72-hour analysis horizon is available even late in a UTC day. One response per provider is reused through the existing bounded cache.
  • Up to 336 hourly timestamps are normalized. Actual live checks returned 288 each. Units must match the requested canonical units; malformed/non-finite/boolean/out-of-range values become null. Unexpected nonzero UTC offsets are rejected. Duplicate hours become unknown, not double-counted or last-write-wins.
  • Report grid: 168 past/current hourly timestamps plus 73 following timestamps (241 rows). Weather eligibility requires a fresh/valid-empty envelope with a current model timestamp no more than three hours old; AQI uses six hours. Upstream timestamps over five minutes ahead are excluded. Eligibility never makes a missing variable usable.
  • Let a = floor_UTC_hour(as_of) and s = a + 1 hour. A future H-hour summary covers (s, s+H], using endpoints s+1h ... s+Hh, for H = 24, 48, 72. The current partial interval is excluded.
  • Precipitation and reference ET₀ are preceding-hour totals in the provider convention; temperature and RH are instantaneous model values. The official provider table documents these distinctions.5
  • A total, mean or maximum is reported only when every expected hourly input is available. Coverage counts accompany the result. P−ET₀ coverage counts matched pairs, not the smaller of two independent counts.
  • Requested coordinates and returned model-grid coordinates are different metadata. No model grid is relabeled as an exact site measurement. Exported JSON includes attribution, documentation URLs, license notes, status, fetch and model-valid times. CSV includes requested coordinates, weather grid, method version and source clocks/URLs.

1. Psychrometric derivatives

Purpose: inspect atmospheric moisture relationships, not plant stress or human health.

For Celsius temperature T and relative humidity RH in percent:

e_s = 0.6108 × exp(17.27 T / (T + 237.3))       kPa
e_a = e_s × RH / 100                          kPa
VPD = max(0, e_s − e_a)                      kPa
L = ln(e_a / 0.6108)
T_dew = 237.3 L / (17.27 − L)                °C

The saturation-pressure expression is the FAO/Tetens form; dew point is its algebraic inverse. Reference: 1.

Guardrails: RH must be 0–100. RH=0 permits finite VPD but no finite dew point. ATLAS conservatively withholds these derivatives outside −40…50°C. This is a liquid-water approximation, not an ice/frost-point model. It does not infer crop water stress from VPD alone.

Checks: saturated RH yields VPD=0 and dew point≈T; known 20°C/50% RH example; RH=0; missing, boolean, out-of-range and non-finite inputs.

2. Atmospheric reference balance

B_H = sum(P_i) − sum(ET0_i), i = 1…H         mm

ET₀ is the provider's FAO-56 well-watered grass reference calculation, not actual site evapotranspiration.5 ATLAS does not recompute Penman–Monteith from incomplete inputs.

What this is not: runoff, soil-water storage change, recharge, irrigation need, drought severity or flood probability. No crop coefficients, rooting depth, field capacity, interception, infiltration, terrain routing, irrigation, groundwater or calibrated water-balance state is available. Negative B is a descriptive atmospheric reference deficit only.

Checks: all expected endpoints; no precipitation/rain double addition; zero is valid; a missing rain or ET₀ hour makes B unknown; matched-pair coverage is tested separately.

3. Configurable capped thermal accumulation

D_H = sum(max(0, min(T_i, cap_C) − base_C)) / 24    °C·day

Default base 10°C, cap 30°C; permitted −10 ≤ base < cap ≤ 50°C. The UI exposes both assumptions. This is an endpoint-temperature integration approximation, not the daily min/max-average convention used by some agronomic degree-day products.

Not provided: crop calibration, growth stage, flowering/harvest date, crop suitability/yield, pest emergence or prescriptions. Displaying chart temperatures in Fahrenheit does not silently change thermal parameters or degree-day units.

Checks: constant-temperature analytic values, lower clipping, upper cap, 24/72-hour scaling, missing intervals and parameter rejection.

4. Wind-direction distribution

Sixteen 22.5° bins; north wraps correctly through 360°. Directions mean where wind comes from. Speeds below 3.6 km/h count as calm, even if direction is unknown. Other missing speed/direction pairs are unknown. The rose covers the next 24 complete intervals; bins + calm + unknown account for all 24.

Mean speed per nonempty bin is a descriptive arithmetic mean. No pollution plume, atmospheric transport or fire-spread forecast is inferred. The table retains explicit km/h units.

5. Small joint-weather novelty model

Purpose: show how a supplied model trajectory differs from its own short recent modeled baseline after removing its regular daily cycle.

Inputs: T (°C), RH (%), wind speed (km/h), surface pressure (hPa). No air-quality predictor or incident label is used.

Fit, in order:

  1. Select complete rows with timestamps in the past seven days and no later than as_of. The canonical grid supplies at most 168 complete training rows. Require ≥72 complete rows and ≥3 observations for every UTC hour.
  2. Estimate 24 hourly medians for each of the four features (96 stored values). Subtract the appropriate hourly center to remove the daily pattern.
  3. Subtract the componentwise residual median. Scale by max(1.4826 × median absolute deviation, floor) with floors (0.5°C, 3%, 1 km/h, 0.5 hPa).
  4. Clip training standardized residuals to ±4 for the covariance estimate. Form sample covariance C; regularize with identity:
λ = clamp(2p/n, 0.2, 0.6), p = 4
Σ = (1 − λ) C + λ I

This is a documented heuristic shrinkage rule, not a fitted Ledoit–Wolf estimator. With the current minimum sample size the lower bound λ=0.2 is active.

  1. For a complete row, use its hour's baseline, residual median and scale. Clip standardized scoring inputs to ±100 as a numerical/output bound, then compute d = sqrt(zᵀ Σ⁻¹ z).
  2. An optional exported baseline rank is 100 × (count(d_train < d) + 0.5 count(d_train = d)) / n. Constant histories therefore have zero distance and rank 50, not a spurious alarm.

Size: 120 stored floating-point parameter entries (including the full symmetric 4×4 matrix), 960 bytes of float64 numeric arrays. This excludes Python/NumPy objects, data arrays, executable code and process memory. No GPU/downloaded weights. NumPy was already a dependency through Shapely; it is now declared directly.

What it does NOT establish: a disaster probability, chi-square tail probability, empirical predictive accuracy, superiority over an operational forecast, independent evidence, a climate anomaly or calibrated out-of-sample confidence. Training and comparison values come from provider models; there is no sensor ground-truth dataset or holdout calibration.

Checks: future-value perturbations leave past fitted scores unchanged; insufficient per-hour coverage is rejected; collinear/constant features remain finite; ranks remain bounded; full JSON rejects non-finite values. These are implementation/invariant checks, not a hazard-validation study.

6. Descriptive robust trend

Theil–Sen: median of pairwise slopes (y_j−y_i)/(t_j−t_i) over up to 96 supplied points; reports units/day. Signal Lab describes the 72-hour provider forecast, requires ≥12 valid samples, and ignores missing values. No future values are extrapolated by ATLAS and no significance/confidence interval is claimed.

Method reference: SciPy's documentation of the median pairwise-slope definition. ATLAS implements this small bounded calculation itself; SciPy is not required.

Checks: known linear slope, single-outlier resistance and insufficient samples.

7. Timestamp-aligned associations

Pairwise Spearman rank correlation over past model rows. Ties receive average ranks. Only same-timestamp nonmissing pairs enter; minimum 48 pairs. Constant or insufficient pairs return null plus a reason/sample count.

Not causality: diurnal patterns, common model forcing, serial correlation and changing coverage can dominate these associations. Raw-series correlations are not partial correlations, causal effects or independent significance tests. No p-values are shown.

Checks: increasing/decreasing rankings, ties, null alignment and constant series.

Comparison and record charts

POST /api/v1/compare permits two or three points, captures one server-side as_of, shares the same forecast windows, and uses the same methods/parameters. It fetches only weather and AQI through the normal cache. No score ranks places as safe/unsafe. Consistent methods/time windows do not imply identical model families, grid resolutions or assimilation across locations. Novelty distances from different local baselines are not compared as a shared hazard scale.

Record charts describe the currently selected map filters. They retain cross-source overlaps. USGS magnitude/depth pairs are restricted to usable values and at most 600 plotted records; magnitude types may differ. Negative reported depth is drawn at the surface and disclosed. Counts are not global occurrence rates, unique incidents, exposed populations or energy measurements. No earthquake energy proxy is shipped: an unverified conversion would add misleading precision without improving the core workflow.

Validation boundaries

No hindcast skill study, sensor validation, agronomic calibration, climatological baseline, benchmarked disaster classifier or production load certification was conducted. Use official authorities and qualified local evidence for consequential decisions. Provider availability, licenses and model versions can change.

Scientific methods and model card

Version: screening-1.0.0 · Validation class: research screening / explicit scenarios, not calibrated disaster prediction.

Core commitments

  • Unknown is not zero, benign, or “average.” Missing fields do not receive made-up environmental values.
  • Provider freshness, data age, model resolution and physical uncertainty are different dimensions.
  • Correlated inputs and duplicated aggregators are not independent evidence.
  • No probability, return period, satellite index or confidence claim is created without the corresponding measurement/validation workflow.

1. Environmental attention screen

Purpose: orient the reader toward available environmental signals. It is a transparent display-priority heuristic, not a trained hazard model, severity authority, probability or all-clear.

Signal Input Weight Piecewise display knots (input → 0–100 score)
Air Modeled US AQI 0.30 0→0, 50→10, 100→30, 150→55, 200→75, 300→100
Heat Modeled temperature °C 0.20 25→0, 35→40, 40→70, 45→90, 50→100
Rain Modeled completed 24-hour precipitation mm 0.20 0→0, 20→15, 50→40, 100→75, 150→100

For available component scores s_i and their weights w_i:

coverage = sum(weights of usable components)
score = 0.65 × max(usable scores)
      + 0.35 × sum(w_i × s_i) / coverage

With no usable signals, score is null. Temperature/wind sanity bounds reject implausible values rather than making extreme alerts from malformed inputs. Missing timestamps cannot establish current attention. Weather is usable only with acceptable provider time (up to three hours old), AQ up to six hours; stale-cache envelopes are excluded from this screen.

The weights, knots and 35/65 mixture are designer choices, not learned or validated coefficients. “Elevated” and “Watch” are UI categories, not official warnings. The heat component is warm-temperature-only: it does not represent frost, wet-bulb stress, individual heat illness or local acclimatization.

Missing-input sensitivity

Unknown component scores are set to 0 and 100 to calculate lower/upper sensitivity bounds using the full weight vector. These are worst/best-case completion bounds, not statistical confidence or prediction intervals. Partial-coverage normalized scores should not be compared between places as though all their information were equivalent.

The index omits exposure, defenses, drainage, vulnerability, building stock, population, lithology, groundwater and many other mechanisms. Related weather inputs are correlated. No flood, landslide, liquefaction, disaster-loss or casualty forecast is produced.

2. Completed-hour precipitation

Open-Meteo hourly precipitation is interpreted as the preceding-hour amount. Anchor to the last completed UTC hour and require exactly 24 valid hourly endpoints. Future forecast values are excluded. Duplicate timestamps do not create duplicate rain. A missing endpoint makes the total unknown; available-hour count is returned.

rain is not added to precipitation. Current 15-minute or hourly instantaneous output is never relabeled as 24-hour accumulation. This is still model output, not a local rain gauge.

3. Fosberg Fire Weather Index (FFWI)

The classic Fosberg calculation uses Fahrenheit, percentage relative humidity and wind in mph. Input conversions are explicit (°F = °C × 9/5 + 32, mph = km/h ÷ 1.609344).

Equilibrium moisture m:
RH < 10:  m = 0.03229 + 0.281073 RH − 0.000578 RH T_F
RH < 50:  m = 2.22749 + 0.160107 RH − 0.01478 T_F
otherwise: m = 21.0606 + 0.005565 RH² − 0.00035 RH T_F − 0.483199 RH

r = clip(m, 0, 30) / 30
η = 1 − 2r + 1.5r² − 0.5r³
FFWI = clip(η × sqrt(1 + wind_mph²) / 0.3002, 0, 100)

FFWI is not ignition probability, fuel availability, fuel moisture measurement or a confirmed wildfire. It does not make a satellite thermal anomaly a wildfire. Tests verify units/range, wind/humidity direction and invalid-input rejection, not operational calibration.

4. SoilGrids predictions

Source: ISRIC SoilGrids documentation; scientific context: Poggio et al., 2021.

  • Nominal resolution: 250 m; static modeled properties, not live soil sensors or laboratory measurements.
  • Queried depths: 0–5, 5–15 and 15–30 cm.
  • Two bounded requests: three-depth means and surface means/Q05/Q95. Failures are normalized independently so a valid half survives a transport or schema failure in the other half.
  • Surface means must agree before combining a separately fetched uncertainty interval. Deeper intervals are unrequested and never interpolated.
  • Unit conversion uses the provider's mandatory d_factor. Examples from the validated response: pH 83/10 = 8.3; SOC 90/10 = 9 g/kg; nitrogen 133/100 = 1.33 g/kg; bulk density 138/100 = 1.38 g/cm³; coarse fragments 73/10 = 7.3% volume.
  • Valid null urban/no-data cells stay null. The default point is explicitly named Agra district · rural east, not quietly substituted for a user-selected city center.
  • Q05–Q95 are marginal provider model prediction quantiles. They are not a site-specific confidence certification or a joint interval for every derived quantity.

Carbon stock, not carbon sequestration

For each depth with complete SOC, bulk density and coarse-fragment inputs:

stock(t C / ha) = SOC(g/kg) × bulk density(g/cm³)
               × thickness(cm) × 0.1 × (1 − coarse fragments(% volume)/100)

Sum the 5, 10 and 15 cm horizons for 0–30 cm stock. If any required input is missing, no stock is returned. The calculation does not estimate soil carbon additionality, sequestration rate, permanence, management response, carbon-credit eligibility or CO₂-equivalent removals.

A calibrated joint interval would require dependence/covariance between predicted SOC, density, fragments and horizons; ATLAS does not multiply marginal interval endpoints and call that a 90% stock interval.

Texture and crop pH

Sand/silt/clay are checked for a plausible compositional total before a broad texture description is returned. This is not a complete USDA texture-triangle classifier.

The crop list compares surface pH only with broad illustrative pH ranges in code. It ignores cultivar, climate, water, salinity, rooting depth, nutrients, pests, economics and management. It is not a crop suitability ranking, a fertilizer recommendation or a yield model. Confirm any field decision with appropriate local sampling and agronomic expertise.

5. RUSLE-style scenario calculator

A = R × K × LS × C × P

Inputs are user-supplied assumptions. R is MJ·mm/(ha·h·year), K is t·h/(MJ·mm), and output is t/(ha·year). The initial slider values are explicitly illustrative and not inferred from the selected location.

The slope-length implementation is a simplified empirical approximation:

  • θ = atan(slope_percent/100);
  • length exponent m = 0.2, 0.3, 0.4, 0.5 for slope bins <1%, <3%, <5%, otherwise;
  • L = (length_m / 22.13)^m;
  • S = 10.8 sin θ + 0.03 below 9%, otherwise 16.8 sin θ − 0.5.

This is not a full RUSLE2 implementation and should not be extrapolated to unusual terrain without expert calibration. It estimates an annual sheet/rill erosion scenario, not a single-storm loss, gullies, riverbank erosion or landslides. Annual erosivity is not generated by multiplying today's rain by 365.

The alternative changes the cover factor. A zero baseline produces an undefined relative ratio (null), not a divide-by-zero or invented percentage. UI results retain their submitted inputs and warn if sliders subsequently change.

7. What scientific validation remains

Arithmetic and contract tests are not empirical validation. Before any safety- or livelihood-critical use, define the target outcome and spatial/temporal support; obtain independently appropriate labels; prevent temporal and spatial leakage; evaluate against simple baselines; use held-out regions/seasons; measure discrimination and calibration separately; analyze missingness and observation coverage; quantify correlated-source dependence; document out-of-distribution behavior; and obtain domain review.

A probability UI, an “AI confidence” badge or a Monte Carlo loop would not substitute for that process. ATLAS deliberately exposes these boundaries rather than disguising them as complete hazard intelligence.

Coverage, outages and costs

“Public” does not mean exhaustive, always-on, unrestricted or authoritative for every decision. Default FIRMS is regional, NWS is US-only, TfL is London-only, ADS-B depends on reception, GBIF is a historical sample, and national population is not local exposure. GeoNames/search and selected coordinates are sent to providers; provider-side logging can apply.

A provider timeout or {} body is not proof that no incidents exist. GDELT was retained as a transparent optional unavailable adapter rather than filled with invented stories. ReliefWeb and other investigated routes were not integrated where the access/schema conditions were not established. CARTO tiles that returned an API-key-required image were removed rather than treated as usable keyless data.

No paid API, hosting plan or account purchase was made. Production resource and provider costs depend on actual audience, licensing and the infrastructure you choose later.

ISRIC access and scale clarification

ISRIC states a public beta REST fair-use limit of 5 API calls per minute and advises against local/farm-level interpretation of SoilGrids. ATLAS now spaces ISRIC calls by at least 12.1 seconds per process and uses one longer bounded attempt, not duplicate cold-query retries. Two soil subqueries consume two calls; cached queries consume none. Shared deployments/replicas need a shared quota, and busy/cold queries can legitimately produce partial or unavailable results. 1

The ATLAS carbon stock is a physical conversion applied to predicted component means; it is not the official separately trained SoilGrids carbon-stock product and need not agree with it. Product-of-means and mean-of-products differ when inputs covary. Treat the displayed point lookup as regional modeled context, never parcel/farm-level precision. 1

ATLAS 2 analysis and portable geometry endpoints

GET /api/v1/insights

Required lat, lon; optional base_c=10, cap_c=30. −10 ≤ base < cap ≤ 50°C. A timezone-aware as_of is accepted only within the bounded near-current window (at most 600 seconds past / 60 seconds future); this is not historical replay. Response includes model/method version, requested point, 241 canonical hourly rows, 24/48/72-hour windows, complete-input counts, wind distribution, tiny novelty model diagnostics, trends, rank associations, clocks and attribution/license metadata. Source failures remain explicit and can yield an unavailable analysis with null fields rather than an HTTP 500. No soil request is made.

POST /api/v1/compare

{"points":[{"lat":27.1,"lon":78.15},{"lat":28.6139,"lon":77.209}],"base_c":10,"cap_c":30}

Two or three points only, input order preserved. Captures one server as_of and applies the same complete forecast windows to each report. No location safety ranking or crop forecast is computed. Boolean/non-finite scientific inputs are rejected. Both endpoints use the same optional X-Atlas-Key protection as the rest of /api/.

POST /api/v1/aoi

Alongside a WGS84 Polygon and hours, v2 accepts minimum_priority (0–5), aware end, and kinds. Omitted/null kinds means no kind restriction; an empty array means no selected kinds. Source filters/position lifetimes match the map and are echoed in the result. ≤200 total ring vertices, ≤3 holes and <180° longitude span; topology/hole validity is checked on the server. Drawing/import/saved camera fitting do not alter this scientific geometry.

Other boundary changes

  • /api/v1/ready uses HTTP 503 before ready, rather than returning success with a false body.
  • Proximity responses disclose eligible/candidate counts and candidate/group/comparison truncation. They do not imply corroboration.
  • Weather/AQI cache keys are versioned to avoid restored short v1 windows. Time strings are normalized timezone-aware UTC; consumers must not append a second Z.
  • Workspace JSON is a client-side portable configuration, not a backend-data import endpoint. It contains selected point, active/saved polygons, filters and display preferences; no keys or historical provider snapshots. Server topology checks still apply when an imported polygon is analyzed.

CHAPTER 09 / SECURITY AND DEPLOYMENT

Security and privacy model

Threat model

The application consumes untrusted public provider responses and accepts untrusted point, search, polygon and scenario input. Internet users can generate costly requests, slow bodies or simultaneous streams. Upstream outages, schema drift, credential mistakes and stale data are considered normal failure conditions.

This document describes implemented controls, not a penetration-test certificate. Safety-critical interpretation is a separate scientific risk addressed in SCIENTIFIC_METHODS.md.

Implemented controls

  • Fixed-origin egress: HTTPS only, exact hostname allowlist, no credentials in authority, no nonstandard ports, no redirect following. No arbitrary-URL proxy. Invalid camera identifiers must also exist in the current official catalog.
  • Validated map metadata: provider-owned versioned tile template must match a strict host/path pattern; glyph stack and Unicode block bounds are restricted. Vector/raster caches and outstanding fetches are bounded.
  • Input boundaries: finite/ranged coordinates and scenario factors; polygon closure/topology/span/vertex/hole validation; 64 KiB bodies and 10-second receive deadline. Body buffering consumes an inflight slot before waiting.
  • Resource controls: deployment-local peer token bucket, 96 inflight requests, 64 SSE listeners, bounded queues, bounded cache count/bytes, limited provider concurrency, budgets and deadlines.
  • Auth: optional X-Atlas-Key; no query-key fallback; constant-time comparison; invalid required-key configuration rejects startup. Settings avoid printing secret fields/validation input. This is a deployment access key, not user accounts, roles or tenant isolation.
  • Credential handling: NASA key stays server-side; browser deployment key stays in page memory, not local storage. Frontend request helpers reject off-origin URLs. Map fetches use same-origin header injection; camera images are fetched as authenticated blobs. Authenticated operation uses snapshot polling instead of a credential in an SSE URL.
  • Parser behavior: defused XML, strict JSON nonfinite rejection, finite numeric parsing, unknown/null preservation, source schema checks, no eval or provider-supplied executable code.
  • Rendering: React text rendering, protocol-filtered source links, no provider HTML injection, bundled scripts/styles/fonts, CSP, nosniff, referrer and permissions policies. Inline styles are allowed for the UI; arbitrary inline scripts are not.
  • Exports: CSV neutralizes common spreadsheet formula prefixes; JSON/GeoJSON preserve typed source/nature/time semantics. Treat externally edited exports as untrusted input in downstream tools.
  • Persistence: SQLite WAL, parameterized queries and bounded logical payload retention; no application visitor/account database.
  • Errors/logs: structured source ID/status/error-type messages instead of full upstream bodies, headers or secret-bearing URLs. Production run scripts disable Uvicorn access logs. This does not configure your reverse proxy, hosting platform or network telemetry for you.

Explicit residual risks / deployment duties

  1. Fixed-host allowlisting is not DNS/socket IP pinning. Enforce a real egress policy blocking loopback, link-local, private/internal and metadata destinations as appropriate; trust/configure DNS and CA roots deliberately. TLS verification is enabled.
  2. Limits, circuit state and budgets are process-local. Restart resets daily counters. Multiple workers/replicas multiply quotas and split SSE state. Use a shared budget store before scaling.
  3. The peer address is taken from ASGI, not untrusted X-Forwarded-For. Behind a proxy all viewers may share one peer budget. Add trusted ingress authentication/rate limiting instead of blindly trusting forwarded headers.
  4. A shared API key is not SSO, MFA, RBAC, audit identity, tenant scoping or key lifecycle management. For a team deployment prefer a mature identity-aware gateway plus appropriate application authorization.
  5. HTTPS/HSTS, trusted hosts, secret rotation, patching, backup/restore, monitoring, incident response and hosting network policies are operator responsibilities. Container/CI examples are provided but were not run on the user's future infrastructure.
  6. The preview intentionally allows framing: there is no frame-ancestors block because Arena's live preview is framed. Set an appropriate production ingress policy; the example Caddy configuration uses frame-ancestors 'none' outside the preview.
  7. Unknown provider license changes or compromised provider data cannot be solved by an HTTP 200 check. Validate semantics, inspect attribution, monitor drift and retain independent checks for consequential decisions.
  8. Automated tests/audits do not cover every vulnerability, parser corner case, browser/GPU, coordinated traffic pattern or dependency advisory published later.

Privacy and data flow

  • No automatic device geolocation is requested. Default coordinates are an explicitly named rural Agra-area demonstration point, not the user's precise address.
  • A searched place or selected coordinates are sent to the relevant upstream services through the backend. Provider logging/terms can apply. Source links, when opened, follow the publisher's own privacy behavior.
  • Parsed environmental/source snapshots are cached. Cache keys can contain rounded coordinates, country or search query, so do not treat the cache as devoid of sensitive context. Protect/delete it according to your deployment's use.
  • Saved location views persist in browser local storage until cleared in Settings; the access key does not. No server-side user profile or view synchronization is implemented.
  • Aircraft are reception-limited public positions, without owner enrichment, persistent track history or extrapolated routes. This is not a private-person tracking service.
  • TfL imagery is restricted to the operator's public catalog; no scraping of private/unlisted cameras, face recognition or people identification.
  • GBIF output suppresses observer names and exact occurrence coordinates; only a small historical context sample is returned. Species presence/absence or abundance is not inferred from it.
  • Audit metadata concerns public repositories. Neither reviewed repository nor its datasets/weights is bundled in the project.

Operational security checklist

Before external launch: choose a non-commercial or appropriately licensed API plan; deploy HTTPS; protect private use with identity/key controls; set trusted ingress limits; restrict egress; configure secrets outside source control; retain one worker until distributed state is implemented; test backup/restore and graceful shutdown; test expected concurrent traffic; rerun dependency audits; arrange alerts on source failures/quota use; verify camera/news/map redistribution terms; and commission security/accessibility/domain review proportionate to the use case.

For a vulnerability report, send a minimal reproduction to the operator you deploy this with. Do not include real provider or deployment keys in public issues, screenshots or examples.

V2 additions

  • Header keys must be 32–256 visible ASCII characters without whitespace/control characters. Client-side settings use the same constraint; server validation remains authoritative.
  • Workspace import is byte/version/type bounded and allowlisted, including active/saved polygons; unknown fields/keys are not exported. It is not a provider-data or arbitrary-URL import.
  • JSON fetches refuse redirects, verify media types, bound streamed bytes/error text and distinguish timeout from intentional cancellation. Image fetches remain MIME/size checked.
  • Comparison is limited to three points; scientific booleans/non-finite values are rejected. Numerical methods are bounded in history/dimensions and run off the event loop.
  • Restored cache timestamps/statuses are validated; SQLite writes rollback on failure. AOI filters and expiring positions match map semantics.
  • Launchers bind to loopback unless explicitly overridden. Publication helper refuses unrelated Git roots/existing origins and common runtime/credential paths, but is not a secret scanner. Review content and history yourself before publication.
  • No remote GitHub publication has occurred in this environment. Authenticate locally using the official CLI/credential helper; never send credentials in chat.
